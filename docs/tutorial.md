# CPIM-MES エンドツーエンド チュートリアル

「BIKE-100 (完成車) を 10台製造する」シナリオを通して、
本システムが実装する CPIM の主要機能を一通り体験できます。
所要時間は約 20 分です。

> 前提: `docker compose up --build` で起動済み、
> `http://localhost:5173` で `admin` / `admin123` にログイン済み。

---

## ステップ 1: マスタデータの確認 (3分)

### 1-1. 品目マスタ
左メニュー **品目マスタ** を開きます。BIKE-100, FRAME-1, WHEEL-1, CHAIN-1 など
初期 seed データが表示されることを確認してください。

行をクリックして編集ダイアログを開くと、
**MRP ロットサイジング方式** (LFL/FOQ/POQ/EOQ) が設定可能です。
- BIKE-100: `FOQ` (固定ロットサイズ)
- TIRE-1:   `EOQ` (経済発注量)
- CHAIN-1:  `POQ` (2期間まとめ発注)

### 1-2. BOM
左メニュー **BOM** を開き、親品目に BIKE-100 を選択。
1階層展開と多階層展開タブを切り替えてみましょう。

### 1-3. 作業区とルーティング
**作業区** で WC-ASSY / WC-WELD / WC-PAINT / WC-PACK の能力レートと
労務費・**間接費レート** が表示されます。
**ルーティング** で BIKE-100 の工程順 (溶接→塗装→組立→梱包) を確認。

---

## ステップ 2: 計画 (5分)

### 2-1. 需要登録
**需要管理** で「2 週間後納期で BIKE-100 × 10台」の需要を1件登録。

### 2-2. 需要予測 (任意)
**需要予測** で BIKE-100 を選択し SMA (移動平均) を実行。
過去90日分の seed データから将来需要を予測し、MAE/MAPE を確認できます。

### 2-3. MPS
**MPS** で BIKE-100 を週次生産計画に登録。

### 2-4. MRP 実行
**MRP実行** ボタンを押すと、BOM 多段展開と FOQ/POQ/EOQ ロットサイジングが
適用された計画オーダが期間別に並びます。
**Pegging 列**で、各計画オーダがどの独立需要から派生したか追跡できます。

### 2-5. CRP 実行
**CRP** で MRP の計画オーダから工程別負荷を算出。
本実装では工程ごとに 1日ずつ後方展開され、棒グラフで作業区毎の負荷率が見えます。

### 2-6. 原価積み上げ
**原価積み上げ** で BIKE-100 の Material + Labor + **Overhead** が確認できます。

---

## ステップ 3: 購買 (3分)

MRP の計画オーダ結果を見て、不足する原料に対して購買発注を作成します。

### 3-1. PO 作成
**購買発注** で `+新規`、品目=FRAME-1、サプライヤ=「Frame Co.」、数量=10、
納期は1週間後で登録。

### 3-2. PO 部分入荷
作成した PO 行で **「入荷」** ボタンをクリックし、今回入荷数量を入力します。
たとえば発注10に対して4だけ入荷すると、POは `PARTIALLY_RECEIVED`、入荷済4、残6になります。
- `receiptId` が自動生成され、同じ要求の再送でも二重入庫されません
- ロット番号を空欄にすると receiptId を含む一意ロット番号が自動採番されます
- 在庫は今回数量だけ増加し、`purchase_receipts` + `inventory_txns(RECEIPT)` + `lot_movements(RECEIPT)` が同時に起票されます
- MRP/ATPでは残6だけが将来のScheduled Receiptとして残ります

残6を後日入荷すると累計10となり `RECEIVED` になります。「履歴」ボタンで各入荷の数量・ロット・受入者を確認できます。

---

## ステップ 4: 製造実行 (5分)

### 4-1. WO 作成
**製造指示** で `+新規`、品目=BIKE-100、数量=10、納期 2週間後で登録。
ステータスは `PLANNED` で作成されます。

### 4-2. WO リリース
作成した WO 行で **「リリース」** ボタンをクリック。
- システムが **WO品目の直下BOMだけ**をRelease時Snapshotとして固定し、そのSnapshotから直下構成品の必要数を計算
- 在庫が十分なら `RESERVE` トランザクションで予約
- 不足があれば `409 Conflict` で拒否

リリース成功後、`v_stock_balance` ビュー (`GET /api/inventory/balance`) で
`reserved` が増加していることを確認できます。

### 4-3. WO 部分完成
ステータスが `RELEASED` になった WO で **「完成入力」** ボタンをクリック。
「今回完成数量」を入力します。BIKE-100 ×10なら、まず4台だけ完成として `4` を入力しても構いません。

システムが以下を **単一の DB トランザクション** で実行:
1. **直下構成品のみ**: 今回4台分だけ `UNRESERVE` + `ISSUE`
2. **FIFO 複数ロット消費**: 今回必要量だけロットから消費
3. 親完成品 BIKE-100: 4台だけ `RECEIPT` + `lot_movements(PRODUCED)`
4. `completed_qty=4`、残6台なのでWOは `IN_PROGRESS`

次回「完成入力」で6を入力すると、残り6台分だけ材料/完成品在庫が動き、累計10で `COMPLETED` になります。
結果ダイアログには今回完成・累計完成・残数量・消費ロットが表示されます。

> 多段BOMでは、親WOがサブアセンブリ配下の原材料まで消費しません。例えば `BIKE → WHEEL → TIRE` なら、BIKE-WOはWHEELだけを消費し、TIREはWHEEL-WOで消費します。

---

## ステップ 5: トレース・分析 (4分)

### 5-1. ロット トレーサビリティ
**ロット追跡** で完成ロットをクリック。**Where-used** タブに
WO への参照が記録され、消費された各部品ロットも辿れます。

### 5-2. ABC 分析
**ABC 分析** ページで、直近12か月の使用数量 × 標準原価（年間使用金額）に基づくパレート分析。
高価値品目 (A クラス) ほど厳格な管理が必要です。

### 5-3. サイクルカウント
**サイクルカウント** で `スケジュール生成` → ABC 連動の棚卸計画が
A=週次/B=月次/C=四半期の頻度で自動生成されます。

### 5-4. ガントチャート
**ガントチャート** で、作成した WO が時系列に表示されることを確認。
ステータス色分けと「本日線」で進捗を一目把握できます。

### 5-5. 監査ログ
**監査ログ** で、これまでの全 POST/PUT/DELETE が
ユーザー名・IPアドレス・リクエストペイロード付きで記録されています。

---

## ステップ 6: API ドキュメント (任意)

http://localhost:8080/api/docs を開くと Swagger UI が起動します。
右上 **Authorize** ボタンで JWT トークンを設定すると、
保護された API を直接ブラウザから試行できます。

---

## ✅ 完了！

このチュートリアルで体験した CPIM 主要領域:

- **Planning**: SOP / Forecast / MPS / MRP / CRP
- **Inventory**: 多階層 BOM / ABC 分析 / サイクルカウント / 在庫予約
- **Costing**: 標準原価積み上げ (Material + Labor + Overhead)
- **Execution**: 業務一貫フロー (WO リリース→PO 入荷→WO 完成)
- **Quality**: ロット トレーサビリティ + Where-used
- **Security**: JWT認証 + RBAC + 監査ログ

次は実データを投入して、自社環境に合わせたカスタマイズに進めます。
