# S&OP → MPS Disaggregation

## Purpose
Convert a monthly family-level S&OP supply plan into auditable item-level MPS buckets without losing planning provenance.

## Flow
1. Assign FG/SA items to an S&OP family in Item Master.
2. Create a Product Mix Version for the family. Mix percentages must total 100%.
3. Activate the mix. The prior ACTIVE version is archived atomically.
4. Select an S&OP monthly plan and preview disaggregation.
5. Publish the preview to MPS. The backend stores an immutable disaggregation run and line snapshot in the same transaction as the MPS updates.

## Quantity rule
Monthly supply is first split by product mix. Each item share is then time-phased into 7-day buckets anchored on the first day of the S&OP month. The final bucket contains the remaining calendar days, so time weights sum to 1.0.

Example for September (30 days): bucket starts are Sep 1, 8, 15, 22, 29 with day weights 7/30, 7/30, 7/30, 7/30, 2/30.

For S&OP supply 1,000 and mix 40/35/25, monthly MPS totals are 400/350/250 and the total remains 1,000.

## Provenance
MPS entries generated by this flow use `demand_basis = SOP_DISAGGREGATION` and retain:
- `source_sop_plan_id`
- `source_sop_disaggregation_run_id`
- `source_product_mix_version_id`

Manual MPS edits clear both Forecast and S&OP provenance. Publishing Forecast Consumption clears S&OP provenance. Publishing S&OP Disaggregation clears Forecast provenance.

## Safety
- Only ACTIVE mix versions can be used.
- Product mix items must be FG/SA members of the same family.
- Product mix total must equal 100%.
- S&OP plan, mix version, audit snapshot and MPS update are transactionally consistent.
- Existing MPS `released` quantity is never reduced; disaggregation is rejected when generated planned quantity would fall below released quantity.
- Database triggers validate MPS values against the immutable disaggregation snapshot.
- Applied runs and lines are append-only audit data.

## Migration
`0026_sop_mps_disaggregation.sql` creates Product Mix versions, immutable disaggregation history and MPS provenance columns. Automatic migration management applies it before API startup.
